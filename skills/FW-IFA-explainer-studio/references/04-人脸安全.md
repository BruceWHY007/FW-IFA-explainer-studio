# 人脸安全：先量，再摆，最后查

这一套规则来自实际返工：标题明明头顶有空间却压在人身上、人物缩进圆窗后脸被切掉、上下或左右排素材时直接盖住半张脸。所以本技能不靠经验值摆位置，每支片先量人物，再按量出来的数摆，最后机器查。

## 1 量（scripts/measure.py）

每 0.5 秒抽一帧（缩到 540 宽），每帧记三样，写进 `geom.json`：

- **人脸框**：x、y、宽、高（换算回 1080×1920）。
- **头顶**：人像分割里第一行有人的位置（含头发）。
- **人体左右边界**：每隔约 12px 一行，记这一行人像的最左和最右。

三种实现，结果可以互换：

| 实现 | 系统 | 安装 | 精度 |
|-|-|-|-|
| `vision` | macOS 12+ | 不用装；第一次运行用 swiftc 编译（没有就 `xcode-select --install`） | 人脸＋人像分割，最准 |
| `mediapipe` | Windows／Linux／macOS | `pip install mediapipe==0.10.14 opencv-python-headless`（Python 3.9–3.12） | 人脸＋人像分割；在 macOS 上和 vision 对比实测：头顶差 1px、脸高差 4% |
| `opencv` | 兜底 | `pip install "opencv-python-headless<5"` | 只有人脸；头顶按脸框往上 0.4 个框高估算，比实测高 40–60px（宁高勿低）；没有人体边界 |

`--backend auto` 按「macOS 用 vision → 装了 mediapipe 用 mediapipe → 否则 opencv」自动选。用了 opencv 兜底，build 会提醒。

## 2 摆（版式代码自动做）

每一段只看这一段时间里的帧，取**最不利**的位置：脸框取并集，头顶取最高。跳切推近会让脸变大 8%，允许推近的段按推近后的位置算。

- **头部范围**＝头顶到下巴、脸框宽度两侧各加 5%（人脸框本来就接近整个头宽）。
- **头顶标题**：可用高度＝头顶 − 22 − 150（150 以上留给平台顶栏）。按行数和字数自动缩字号，缩到 55% 还放不下就报错。
- **两侧标签**：高度对齐下巴；宽度＝头部范围外侧剩余空间（最多 300），不到 220 就报错。
- **身前元素**（卡片、名牌、数字、贴纸、环）：上沿不高于下巴＋0.3–0.4 个脸高。
- **量表**：放在离脸更远的一侧。
- **小窗取景**：圆窗让脸高占窗口 40%，脸中心在窗口 48% 高度；竖窗脸高占 24%、在 36% 高度；圆角方窗 36%、46%。同时保证这一段脸的活动范围装得下、画面铺满窗口不露边。

## 3 查（build.py 自动做）

每个压在人物画面上的元素都登记了范围。build 结束时逐个和头部范围求交，有重叠就报错并给出两个矩形的坐标，**不生成工程**。不要用 `data.pip` 或手改坐标绕过去，换版式（例如两侧放不下就改 `chest_cards`）。

## 常见情况

- **人偏到一侧**：两侧标签一边放不下 → 改 `chest_cards` 或 `gauge`（会自动放到空的一侧）。
- **头顶空间小**（人站得高、构图紧）：头顶标题只放一行，或者这一段改成图解段，标题放进图解段里。
- **人动得多**：脸框并集变大，空间变小；把这一段拆短。
- **换了剪辑**：重新跑 measure.py。geom.json 的时间轴必须和剪好的 aroll.mp4 一致。
